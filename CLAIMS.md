# CLAIMS.md: what is measured, what is estimated, what is not claimed

Every number shown publicly (README, docs, firmware output, demo page) must have a line here with the
script that produces it, the hardware, the commit and the date. If a number has no line, it must not be published.

Status values: **measured** (instrument on the target), **host-measured** (desktop CPU), **estimate**
(computed from assumed constants), **withdrawn** (removed because it was not measured or was wrong).

## Withdrawn claims

| Former claim | Why withdrawn |
| :--- | :--- |
| "2.37 nJ per inference" | Unit error. The same computation gives µJ. |
| "8,193 cycles, 170.69 µs, 2.37 µJ at 48 MHz" for the BPTN layer (and the 0.50 cycle per synapse per step derived from it) | The firmware never set the clock: the board ran at its 4 MHz reset clock with 0 Flash wait states, so the 48 MHz times were wrong, and constant inputs let the compiler move work out of the loop. Measured again at 48 MHz: 11,972 cycles, 249.42 µs. |
| BPTN operators in "6 cycles (125 ns)", "512 million ops/s", "5.3 billion states/s" | Constant inputs folded by the compiler, at 4 MHz. |
| "BPTN engine executes in 0.063 cycle/tick, outperforming all continuous analog models" and "INT8 quantization delivers a real speedup" (`main.rs` conclusion) | The 4-cycle BPTN figure was a constant folded by the compiler (95 cycles once protected); no comparison of models was made. The INT8 claim relied on an unprotected loop. Conclusions removed. |
| Sentinel firmware: "TinyML ~45,000 cycles", "57.3× faster", "~4.2 mA vs ~18 µA", "99.6 % energy reduction", "> 8 years on 1200 mAh coin cell", "CPU WFI sleep 99.8 %" | Typed constants, not measured. Removed; the firmware now prints only its measured cycles and the CPU busy fraction computed from them. |
| "2.3× faster than LIF SNN, 7.1× faster than Micro-GRU on silicon" | The LIF (about 18,500 cycles) and GRU (about 58,000 cycles) figures were constants typed into the firmware, never measured. |
| "5.34 nJ / 16.75 nJ for LIF / GRU", "144 B / 850 B SRAM", "256 / 1,800 MACs" | Same: typed constants. |
| "More than 10 years on a CR2032" | Counted computation energy only; ignored sleep current, wake-ups, sensor, microphone, radio. |
| "0.40 µJ vs 0.03 µJ", "45,000 vs 773 cycles", "4.2 mA vs 18 µA standby" (README comparison table) | Not produced by any script in the repository; the 40 nm ASIC energy constants (0.1 pJ per AC, 3.1 pJ per MAC) do not describe a Cortex-M. |
| "BPTN 14× to 27× faster in block mode, LIF 2.7× to 4.9× faster in streaming" (example 09, 64 neurons × 16 channels) | The models had arbitrary weights and did not solve the same task (2.2 M vs 102 M output spikes), so the ratios compared unrelated computations. Example 09 now uses one shared task with accuracy. |
| Per-operation energy figures from `EnergyEstimator::estimate_picojoules*` (0.1 pJ per AC and 3.1 pJ per MAC for a 40 nm ASIC; 150 pJ and 450 pJ for a "Cortex-M4") in examples 05, 06 and 12 | ASIC constants do not describe a microcontroller, and the Cortex-M4 constants were never measured. The functions are deprecated; `EnergyEstimator::cpu_active_nanojoules` computes cycles × active power / clock instead. |
| "Learned LUT network 5 to 12 points better than the binarized network at equal cycles", then "about 2 to 3 points" | The first figure used a 5 KB micro-benchmark cost; the second compared measured LUT cycles with estimated BNN cycles that were 1.55× too high. Both measured on the board: no significant accuracy difference at equal cycles. |
| "Unbiased round-to-nearest" for Fix32 | The implementation rounds half up. |
| "SHD cochlea benchmark" | The data is synthetic (8 channels, 4 classes), not Spiking Heidelberg Digits. Example renamed `05_synthetic_cochlea_demo`. |
| "MLPerf Tiny submission", "Official managed component" for ESP-IDF, installation from crates.io | Nothing was submitted or published. |
| "KEYWORD DETECTED" in the firmware demo | The demo tested one bit of a framing buffer, not a keyword detector. |
| "Multi-class KWS classification on real acoustic signals" (`silicon_test_runner`, suite 4) | The four inputs are bit patterns written by hand, not recorded audio. The suite is kept as a functional test of the BPTN layer and labelled as such. |
